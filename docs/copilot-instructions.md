# doanson44.github.io — Project Conventions

## Project Identity
`doanson44.github.io` is a **client-side-first Web Utility Hub + Personal Portfolio + Playground** built with Rust/Leptos 0.7 CSR/WASM.

Primary areas: Home, Tools, Games, CV, Socket, and shared platform infrastructure.

## Technology Constraints
- Rust edition 2021, `wasm32-unknown-unknown`, Leptos 0.7 CSR only, Trunk
- Tailwind CSS 4.x through the Tailwind CLI, generated by the Trunk pre-build hook
- Project-owned SVG/text iconography; no external icon CSS dependency
- GitHub Pages deployment (`public_url = "/"`, `dist = "dist"`)
- Feature-specific dependencies only when justified

## Platform Architecture
```
src/
├── main.rs
├── lib.rs
├── app.rs
├── components/      # Shared presentation
├── features/        # Feature presentation + state
├── application/     # Services + ports
├── domain/          # Pure Rust business logic
└── infrastructure/  # Browser/JS/HTTP/WebSocket adapters
```

### Layer Rules
- Domain MUST NOT depend on Leptos, web-sys, wasm-bindgen, or browser APIs.
- Application coordinates Domain and Ports.
- Infrastructure wraps browser, JavaScript, HTTP, and WebSocket APIs.
- Features own reactive state and presentation.
- Components must not bypass Application services to call Domain directly.

## Leptos 0.7 Patterns
Use `RwSignal`, `Memo`, `NodeRef`, `Effect`, `leptos::task::spawn_local`, and `event_target_value` appropriately. Prefer reactive state over manual DOM manipulation.

## UI / UX
- Tailwind CSS utilities are the default styling mechanism.
- Theme uses `data-theme="dark|light"` on `<html>` and project `--ms-*` tokens.
- No Bootstrap classes, Bootstrap variables, Bootstrap JavaScript, or icon-font dependencies.
- No inline `style="..."` in Leptos views.
- Icon-only controls require an accessible name and visible focus.
- Never use pure-black UI backgrounds.
- Responsive at 375/576/768/1024/1280/1920px with no accidental horizontal scrolling.
- WCAG 2.1 AA and no color-only state indicators.

## Shared SVG Icon Rules (Mandatory for Every Agent)

- Use the shared project icon system: `src/components/icons.rs` (`Icon`, `IconName`) and `public/icons.svg`. Import `Icon` and `IconName` from `crate::components::icons`.
- Do not use emoji, Unicode pictographs, arrows, dingbats, or decorative special characters as UI icons. Use a semantic `IconName` instead. This rule is about UI/iconography; normal language, code samples, and user-authored content may contain Unicode.
- Do not add icon fonts, external icon CSS packages, duplicated inline SVG path markup in feature pages, or one-off icon systems.
- Before changing an icon, inspect the function signature and expected type. Keep textual metadata as text: methods returning `&'static str` (such as `slug()` and `title()`) must return string literals; methods returning `IconName` (such as `icon()`) must return `IconName::Variant`. Never blindly replace a text value with an icon enum or vice versa.
- When adding an icon, update both the `IconName` enum / ID mapping and the matching `<symbol>` in `public/icons.svg`. Keep IDs unique, symbols monochrome and based on `currentColor`, and preserve the component's accessibility behavior.
- Icon-only buttons and links must have an accessible name (visible text, `aria-label`, or appropriate `title`) and visible keyboard focus. Decorative icons must not duplicate the accessible name.
- After icon refactors, inspect changed files for leftover UI glyphs and type mismatches; run the repository validation commands that are available. Report each check as passed, failed, or not run—never imply compilation was verified without running it.

## Anti-Patterns
- Domain importing browser/framework APIs
- Components bypassing Application services
- Hardcoded UI colors instead of semantic tokens
- Feature logic in global components
- Assuming GitHub Pages hosts a WebSocket server
- Claiming validation passed without running it
- Unrelated refactors during focused work

## Core Rule
Treat the repository as a Rust/Leptos/WASM multi-feature web platform deployed to GitHub Pages, with Tailwind CSS as its UI styling system.
